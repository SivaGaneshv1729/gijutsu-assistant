# ADR-007: Local LLM via Ollama

## Status
Accepted

## Context
The RAG pipeline needs a text-generation model to convert retrieved chunks into polished, grounded answers. The initial codebase imported `openai` and referenced a `gpt-4o` configuration, but no LLM call was implemented — answers were mocked by concatenating retrieved text. Paid APIs (OpenAI, Anthropic) carry per-token costs, which conflicts with the requirement to run the platform at **zero cost**. The earlier Hugging Face free-tier approach required an API key, had rate limits, and cold-start issues.

## Decision
Use **Ollama** as the default LLM provider, running a local model on the host machine:

- Ollama runs as a Docker container (port `11434`) in the same `docker-compose` stack.
- Default model: `mistral` (7B, fast instruction following, 4-bit quantized).
- Pull the model once: `docker exec -it ... ollama pull mistral`
- No API key required. All inference happens locally.
- If Ollama is unreachable, fall back to an **extractive answer** (the top matching chunk), so the platform remains functional without any external dependency.

## Consequences
- **Pros**: Zero license or zero usage cost. No rate limits. No cold starts. No data leaves the machine. Configurable via a single environment variable (`OLLAMA_MODEL`). Model options range from small (`phi3`, 3.8B) to large (`llama3.1`, 70B) depending on hardware.
- **Cons**: Requires a machine with sufficient RAM/VRAM for the chosen model (7B ≈ 4–8 GB RAM). Initial model download is ~4 GB. Inference is slower than cloud APIs on CPU-only machines, though acceptable for interactive use.
