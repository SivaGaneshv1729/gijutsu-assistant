# ADR-005: Why RBAC Before Retrieval

## Status
Accepted

## Context
Different users have varying clearance levels. Operators should not access restricted engineering designs, while Engineers have full access. If we retrieve all documents and then filter them *after* the fact, we risk returning zero results if the top-K retrieved documents all happen to be unauthorized for the user.

## Decision
Role-Based Access Control (RBAC) must occur *during* the retrieval query, not post-retrieval. For pgvector, this means adding `WHERE document_access_level <= user_access_level` directly to the ANN search query.

## Consequences
- **Pros**: Guarantees secure data access. Prevents "empty" results when top vector matches are hidden. No risk of accidental context leakage.
- **Cons**: Requires embedding metadata/permissions directly alongside vectors and keyword indexes, complicating index synchronization slightly.
