# ADR-004: Why Neo4j

## Status
Accepted

## Context
Industrial machinery is composed of deeply nested hierarchies (Machine -> Assembly -> Subassembly -> Component). Relying entirely on text embeddings struggles to accurately capture these hierarchical relationships and troubleshooting paths (Alarm -> Possible Cause -> Procedure).

## Decision
Incorporate a Knowledge Graph using Neo4j to explicitly model entities (Machines, Components, Alarms, Documents) and their relationships.

## Consequences
- **Pros**: Enables structured querying of relationships. When an alarm is detected, the graph can instantly provide the related components and specific manual sections without relying on vector similarity.
- **Cons**: Requires an additional database in the stack. Extracting entities accurately from unstructured text adds pipeline complexity.
