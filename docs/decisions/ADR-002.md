# ADR-002: Why Hybrid Retrieval

## Status
Accepted

## Context
Relying solely on dense embeddings (e.g., pgvector with sentence-transformers) often fails to retrieve exact matches for model numbers, error codes (e.g., E101), and highly specific technical terminology that industrial documentation is full of. Relying solely on keyword search (BM25) fails to capture semantic meaning (e.g., "cooling issue" vs "temperature regulation").

## Decision
Implement a Hybrid Retrieval architecture using Reciprocal Rank Fusion (RRF):
1. **Dense Retrieval** via pgvector
2. **Keyword Retrieval** via OpenSearch/BM25

## Consequences
- **Pros**: Drastically improved recall and precision for both semantic concepts and specific identifiers.
- **Cons**: Requires maintaining two separate indexes and combining scores.
